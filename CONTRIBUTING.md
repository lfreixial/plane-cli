# Contributing

Bug reports, documentation fixes, and focused pull requests are welcome.
For substantial features, open an issue first to discuss the intended commands
and Plane API support. Keep discussions respectful and constructive.

## Development

Install Go 1.25 or newer and Git, fork the repository, and create a branch for
your change. From your checkout:

```sh
go mod download
go test -race ./...
go vet ./...
go build -o bin/ ./cmd/plane
```

Use `gofmt` on changed Go files. Add regression coverage for behavior changes;
tests use local mock HTTP servers and must not require real Plane credentials.
Run `go mod tidy` after dependency changes. License notices are regenerated by
the release workflow; see [third_party/README.md](third_party/README.md).

Submit a pull request describing the problem, resulting behavior, and validation.
CI must pass before merging. Contributions are made under the repository's
[MIT license](LICENSE); preserve attribution when including third-party code.

## Bug reports

Include the CLI version (`plane --version`), OS/architecture, Plane version
(for self-hosted deployments), sanitized command, expected behavior, and actual
output. A minimal reproduction is especially useful.

Remove API keys, cookies, private hostnames, personal information, and workspace
content before sharing output. Do not attach your config file. Security issues
belong in the private process described in [SECURITY.md](SECURITY.md).

## Live compatibility checks

Before a release, use a disposable project on each supported Plane deployment
you can test. Verify setup, project selection, issue creation/listing/viewing,
editing, state changes, assignment, comments, cycle/module membership, and
deletion of the test resources. Record the Plane and CLI versions in the release
PR. Automated mock tests alone do not establish live API compatibility.
